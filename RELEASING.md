# Releasing V1

The package and userscript versions remain `1.0.0`. `v1` is the moving release channel for the independent rewrite. The historical `v1.0.0` tag remains unchanged.

1. Merge the intended source into `main` and wait for CI on that exact commit.
2. Run the **Publish V1** workflow at the intended commit. It independently validates, builds and runs browser fixtures before publishing.
3. Verify the `v1` tag commit, eight release assets and checksums. A successful build alone does not establish publication.

The workflow explicitly moves only `v1`; it never rewrites `v1.0.0` or another historical tag. Release assets include both userscripts, both metadata files, SHA256SUMS and all three applicable license/notice files. Source archives are generated by GitHub from the tag.

Because the numeric version is fixed, already-installed V1 userscripts may need manual reinstallation to receive a later V1 build. Document this when announcing an update. Do not imply that a same-version userscript update will install automatically.
